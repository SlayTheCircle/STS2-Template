# 验证与测试纪律

不要为了测试而测试。新增或保留验证应能说明触发条件、会发现的合理缺陷及实际后果。测试数量、覆盖率、代码行数和固定内容数量都不作为质量目标。

## 验证层次

| 层次 | 能证明什么 | 需要什么 |
|---|---|---|
| 源码检查 | Git 跟踪边界、文档链接、本地化占位符／覆盖／双语键、公开卡表与内容覆盖、显式文本资源 | Git、Bash、Python；不要求私有媒体和游戏 DLL |
| DLL 编译 | 当前引用版本下可编译、入口存在 | 固定 SDK、同游戏分支引用、RitsuLib |
| 完整素材检查 | 模型资源槽与场景引用都存在 | 完整本地素材；占位图存在不代表美工真图交付 |
| PCK 验证 | 打包后代表性纹理可加载、本地化表可读 | Godot 与真实 PCK |
| 游戏内验收 | 模型注册、场景、机制、存档和原版联动真实生效 | 对应版本游戏与实际试玩 |

命令见 [构建管线](pipeline.md)。源码模式显式跳过媒体存在性；完整模式缺素材必须失败。花名册读取公开设计卡表，默认不依赖私有输入；缺失或空表报错。它核对覆盖，不核对各卡数值和升级。不得用成功退出、返回类型或静态图片存在代替实际效果。

## 用例准入与断言

优先使用能观察目标行为的最窄既有层次。期望来自设计、原版机制、协议／资源格式、存档或玩家可观察结果。可调数值和普通文案不自动逐字锁定；外部消费的字段、复合 ID、生命周期或发行版本有稳定契约时精确检查。

避免构造后原样回读、验证替身、复制待测算法、源代码片段匹配、场景未触发、空洞否定、只断言非空、跨层重复和无依据的数据堆积。Mock 只控制依赖边界，保留目标判断与副作用。并发使用明确同步点；时间和随机性可控。删除低价值用例不要求补足数量。

静态审计保护真实接线风险：本地化占位符、复合键覆盖、媒体误入 Git、缺资源槽和失效文档链接。它们的结果仍有证据边界。例如打击标签的声明与编译可以核对，但 +3 伤害结算应经过实际游戏路径确认。

## 模板管线验证

模板源码回归可运行 `python3 -m unittest discover -s tests/TemplatePipeline -v`。它在临时初始 Git 索引中使用当前源码快照，不创建提交，保护先检查再派生、RitsuLib 复合键、显示名的 Shell／VDF 数据语义、递归本地化和改名前依赖拒绝；还保护计算配套/旧消费键、传递继承内容漏检、X 导表、批次延后与安装清单目标错配。

准备配对引用和工具后，诊断素材的完整管线验证使用：

```bash
python3 tests/TemplatePipeline/smoke.py \
  --refs-1110 '<0.111.0 编译引用>' --refs-1071 '<0.107.1 编译引用>' \
  --ritsulib '<完整 RitsuLib 包>' --dotnet '<dotnet 可执行文件>' \
  --godot '<Godot 4.5.1 标准版可执行文件>'
```

该验证在临时目录生成诊断母版并实际派生、编译、打包，检查缺母版拒绝、字节幂等和包内错尺寸拒绝。诊断图不代表角色正式美术；全过程不部署或上传。模板一次性测试和派生脚手架从衍生仓移除，其内容与运行验收由衍生仓按自身设计建立。

## 可选实现示例验证

[examples](../../examples/README.md)不进入默认内容程序集；[ContentExamples](../../tests/ContentExamples/ContentExamples.csproj)实际链接这些源文件，避免指南中的 API 漂移。加载本机配置后按同样配对引用编译两次：

```bash
source scripts/dev-env.sh
mod_require_refs
mod_dotnet build tests/ContentExamples/ContentExamples.csproj -c Release
mod_dotnet tests/ContentExamples/bin/Release/net9.0/ContentExamples.dll \
  "$GAME_REFS_DIR" "$RITSULIB_DIR/compat/$RITSULIB_TARGET" "$RITSULIB_DIR/shared" \
  '<对应游戏运行依赖目录>'
```

脚本函数需在 Bash 中使用。旧目标先设置该目标的 GAME_REFS_DIR 与 RITSULIB_TARGET 再 source；两次 build/run 顺序执行，因为使用同一个输出目录。纯托管探针只实例化所需卡牌，显式给保存卡提供 canonical 关联和属性缓存，保留真实 DynamicVars、ClonePreservingMutability、SavedProperties 与 UpgradeInternal。它保护缺变量初始化、克隆共享变量、保存增量丢失及升级重复累加，不启动完整游戏、网络 ID 表、战斗或 UI。

该托管探针不执行遗物、事件或时间线；这些示例可配对编译，其原生初始化、支付/取消和自然解锁须在游戏场景中验收。不要在没有 Godot 宿主的进程中强行执行原生内容，也不要把编译或托管字段恢复写成完整存档通过。

## 角色发行验收

在实际发行的各个游戏目标中确认：

- 自己的设计清单与实现、双语文本、升级及资源槽一致，待裁定和未完成项明确记录。
- 菜单、开局、战斗、奖励、选牌取消与机制清理符合设计；可选事件、世界线和对话分别经过自然进度与目标界面验证。
- 新档/已有档、存读档和多人归属覆盖受变更影响的场景；原版联动使用真实卡源、标签与获取时映射。
- 注册 ERROR、缺图和异常都有处理结论；实际加载的二进制与被验收候选包一致。

## 结果记录

报告所运行命令、目标游戏／依赖版本、观察结果以及跳过／未验证项目。完整构建成功不等于游戏验收通过；CI 没有游戏与美术时只报告源码检查。发布前从独立干净目录验证源码，再用完整本地环境验收实际发行物。

## 可选动画工具回归

先读[动画入门](animation/README.md)。工具的独立回归：

```bash
python3 tests/AnimationTools/smoke.py --godot <Godot可执行文件> --render
```

`--render` 需要图形会话（无桌面时可用 xvfb-run）。检查场景保存／PCK 重载、预览启动、生成字节与修改时间稳定、缺动作拒绝、真实渲染前景遮挡、故意抬高部件层级后的失败对照及帧导出。另保护带外部脚本的场景重存时资源 ID 不碰撞、用户字符串不被改写，无效节点／属性轨道被拒绝而嵌套属性及禁用轨道合法；降低帧率向已有导出目录重导时拒绝且保留原字节与修改时间。省略该参数只执行无需渲染器的检查。C# 接线例子和工厂接口接线随 ContentExamples 编译，两游戏目标分别执行。

`python3 -m unittest discover -s tests/TemplatePipeline -v` 另覆盖嵌套部署、备份、进程检测拒绝和工坊身份／简介核对。它使用临时目录与模拟输入，实际游戏及线上发布由派生项目验证。

同一回归集还验证可选工坊更新说明的真实换行与引号转义、未提供时省略字段；图标审查工具使用临时派生身份和诊断图片，检查缩写复合键对应的本地化名称、内嵌图片、修改前对照、描边与素材字节／mtime 不变。页面的实际视觉判断按[素材审查说明](assets.md#图标审查页)人工完成。
