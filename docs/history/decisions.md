# 方案取舍

本页记录模板自身的已采纳决策与理由；相关实现与验证入口直接链接到本仓文档和工具。

## 参数化优先于纯 sed 改名

身份重复硬编码会让脚本、工作流与内容工程发生漂移。根清单是唯一事实源，`modmeta.py` 统一计算身份与复合键，`dev-env.sh` 导出 `MOD_ID`／`MOD_SHORT`／`MOD_LOC_PREFIX`。一次性派生由 `scripts/derivation/` 改写清单、目录、命名空间、类型名与本地化键；来源记录独立保留。验证方法见[验证纪律](../dev/testing.md)。

## 示例内容用前缀式命名

示例类采用 `TemplateStrike` 形态的统一前缀，使派生工具可以同步替换类文件与类型名。命名空间、资源名和本地化键分别按其契约改写；复合键遵循 RitsuLib 规范，不从显示名或简单词边界推断。调整替换规则时运行派生回归，覆盖缩写、多词短名和特殊显示名。

## 世界线不入骨架代码

故事、章节奖励与解锁条件取决于具体角色设计，骨架只保留最小编译链。接线、纪元双肖像槽、三池门控和对话轮次由[世界线手册](../dev/worldline.md)说明，衍生仓按同版本原版先例与 RitsuLib API 实现。媒体仍由私有输入供给，模块完成后独立验收目标界面和内容可获得性。

## Loader 拷贝而非共享库

变体 Loader 以源码拷贝形式进每个衍生仓。理由：两个 Mod 规模下共享库增加依赖与版本协调成本；Loader 是最怕游戏版本更新的资产，拷贝让各 Mod 可独立热修。**触发线**：第三个 Mod 出现，或下一次游戏版本破坏加载链——届时抽为组织共享库（记录于[路线图](../roadmap.md)）。

## 私有侧走跟踪 templates/ 目录

`local_dev/` 整体忽略是仓库边界铁律，但纯私有侧文件到不了模板消费者。取舍：公开仓带 `templates/` 目录存放无密钥的脚手架（publish.sh 骨架、README 衍生视角等），init 时拷入 `local_dev/` 并预填配置，随后从衍生树删除。

## 身份三查入审计

audit-repository 增加「根目录恰一个 json 清单 + 文件名与 id 一致 + `src/<id>/` 存在」三项结构检查：参数化体系完全建立在「清单可被唯一发现且自洽」之上，破坏即大声失败。

## 模板仓不打 git tag

tag 会触发 Release 工作流,而模板仓没有发行物、也不持有构建凭据——首次 v1 tag 即触发了注定失败的 Release 构建(已删)。模板版本以 CHANGELOG 与 `.template-origin` 的 version 字段记录；派生时增加快照 commit 与文件内容 digest，详见新仓上手。
