# 独立开发专项审查（2026-10-02）

本轮审查已完成输入适配、公开开发路径、事故防护和工程管线的复核。以下是修复前的审查快照：模板能够独立派生、编译并产生双目标安装包，但当时不足以让贡献者仅依照现有指南与检查可靠完成复杂角色的全套实现；两条路径未通过完整开发准入。后续整改证据记录在文末，当前状态以 [STATUS](../../../STATUS.md) 为准。

## 输入与证据边界

本机路径使用一份真实、手工整理的设计与美术交付包，核对原案、升级参考、机制、生成卡、遗物、药水、事件、章节、对话和资源。原件、清单、摘要、日志与复现脚本保留在私有工作区，从 `local_dev/README.md` 导航；公开报告不分发设计原件或素材。

外部路径使用当前工作树的公开源码快照，在临时 Git 初始索引中执行派生，并配置独立仓库身份及显式依赖。没有复制维护者的 local_dev、其他角色实现或组织凭据。编译使用本机提供的游戏引用、RitsuLib 0.6.2、.NET 9.0.318、Godot 4.5.1 与 ImageMagick。它证明本机隔离起步的工程行为，不等于远端已提交版本的干净克隆、另一台机器或 GitHub Actions 已经验收。

实际执行了真实素材的显式适配、完整构建、PCK 校验、双目标打包及部署保护的拒绝分支；没有实现整份设计，没有启动真实游戏、部署、上传或发布。错误模型探针使用真实 DLL 在托管进程中实例化卡牌，不等于游戏内验收。审查不会要求模板预置每种角色机制，但要求示例、文档和检查准确说明可用能力与缺口。

## 发现与优先级

P1 表示可能导致初始化失败、关键审计静默遗漏或发行兼容声明错误；P2 表示输入适配、实现指导或设计核对缺口。共 3 项 P1、6 项 P2。

### F01 · P1 · 计算变量缺少配套项仍被检查放行

在示例卡中只声明 `CalculatedDamageVar(ValueProp.Move).WithMultiplier(...)`，文本与结算均改用 CalculatedDamage，省略 CalculationBaseVar 与 ExtraDamageVar。导表、完整源码检查和 DLL 编译均通过；使用真实游戏/RitsuLib DLL 初始化模型时，访问 DynamicVars 抛出 `KeyNotFoundException: CalculationBase`。

[占位符检查](../../../scripts/audit-placeholders.py)只核对文本中的键是否有声明，不核对计算变量依赖或源码消费方。原版 CalculatedVar 的 SetOwner 会更新值并查询 CalculationBase；当前[卡牌手册](../../dev/cards.md)虽然规定三件套，自动门禁没有执行这条规则。补齐必要组合检查，并增加真实模型初始化的回归证据；消费键与倍率接线也须纳入明确的验证范围。

### F02 · P1 · 中间内容基类可绕过多项审计

新增抽象机制基类继承角色 CardBase，再注册一张继承该机制基类的具体卡。故意不供本地化、花名册或卡图。源码检查和编译通过，导出卡表仍只有原来的三张示例。

[占位符](../../../scripts/audit-placeholders.py)、[花名册](../../../scripts/audit-roster.py)、[卡表](../../../scripts/export-card-table.py)与[纹理契约](../../../scripts/asset_contract.py)都按直接继承角色 Base 的文本形态识别内容，没有沿继承链发现后代。应统一内容发现规则，覆盖具体注册模型和传递继承，并排除抽象辅助类；复杂机制拆分不能使内容从检查视野消失。本次未另外验证该卡进入真实奖励池。

### F03 · P1 · 平铺完整构建声明错误的游戏目标

使用 0.111.0 配对引用执行完整 `build.sh` 成功，但 `mods-dist/<ModId>/<ModId>.json` 仍声明 `min_game_version=0.107.1`。[构建脚本](../../../scripts/build.sh)直接复制根清单，没有按实际编译目标生成声明；该目录又是部署来源。

`package.sh` 产生的两个目标 ZIP 分别正确声明 0.107.1 和 0.111.0，问题仅指平铺构建目录及其安装路径。应让所有可安装输出的目标声明与编译引用一致，或拒绝错误组合。未验证新版 DLL 在旧游戏中的具体故障，不能把兼容声明错配写成已经复现的游戏崩溃。

### F04 · P2 · X 费用导表显示为 0

按原版写法使用 `HasEnergyCostX => true`、构造器基础费用 0，导表和源码检查通过，卡表费用却显示为 0。[导出器](../../../scripts/export-card-table.py)只解析构造参数，没有读取 X 费用声明。公开卡牌指南也缺少 X 费用和结算读取入口的示范。

应正确导出 X，并给出同版本原版的费用结算示例。不能将 X 表示为构造器 -1 来掩盖此问题。

### F05 · P2 · 母版映射绑定固定目录和 PNG 扩展名

真实母版中的 JPEG 卡图及另名图标目录分别导致 prep-art 在预检中拒绝，嵌套 PNG 则能通过含相对子路径的映射成功转换。[源文件预检](../../../scripts/art/validate-sources.sh)与各生成模块硬编码 `卡图/<键>.png`、`buff图标/<键>.png` 等约定。

缺件时拒绝是正确行为，问题是没有完整路径和格式的独立绑定接口。建议用“源文件相对路径（含扩展名）→逻辑内容/资源槽”映射，使原件保持不动。手工交付可以探索并由人确认，不能假定未来 ZIP 的目录、文件名或后缀严格一致。

### F06 · P2 · 完整花名册与小批次开发缺少衔接说明

按[内容 SOP](../../dev/content-sop.md)先录完整花名册、后按小批次铺类与文本，第一轮检查因未实现条目和残留示例立即失败。[花名册检查](../../../scripts/audit-roster.py)具备 DEFERRED/TOKENS/ADDITIONS 手工集合，但指南未说明如何登记计划批次、同步移除示例、补齐原案其他章节中的生成卡，以及发行前清零延后项。

未实装条目被拒绝本身符合审计目的。缺口是可执行的分批流程与完整覆盖清单；应显式区分计划、实现、裁定和验收状态，避免删减原案来使检查通过。花名册仍不能替代升级数值、遗物、药水、事件、对话和章节核对。

### F07 · P2 · 克隆与持久状态缺少可复用的完整示范

现有示例不覆盖复制卡效果、可变实例状态、战斗克隆、存档恢复、跨战斗计数器与取消选牌后的状态处理。指南有生命周期原则，但缺少 SavedProperty 等持久化入口的最小完整示范与对应验收路径。

不要求模板包含角色专属机制。应从同版本原版提取通用示例，明确每种状态的宿主、复制、保存、恢复和清理，并说明选择取消、多人归属、随机源与结算顺序。仅列 API 名称不能证明完整设计已经可以按指南实现。

### F08 · P2 · 可选模块指南缺少必要类型与资源接线

[世界线指南](../../dev/worldline.md)只列 Relic/Potion/CardUnlockEpochTemplate，并将每章描述为三件奖励；RitsuLib 0.6.2 还提供 `CharacterUnlockEpochTemplate<TCharacter>`，角色解锁章需要单独说明，不能套用三件内容解锁。故事注册、纪元绑定、条件、奖励和三池过滤缺完整最小例。

[事件指南](../../dev/events.md)列出肖像路径，但 EventBase 没有覆写资产档案；RitsuLib ModEventTemplate 默认 AssetProfile.Empty，肖像由 InitialPortraitPath 接入。放置文件不能证明图片已接线。应补包含资产档案、注册、选项、结果页与验收的完整最小事件，同时保留原版追加选项的独立补丁入口。对话与章节仍须分别做自然进度验收。

### F09 · P2 · 公开说明残留组织假设与兼容能力过度表述

[新仓上手](../../dev/onboarding.md)的私有侧仍要求创建固定组织下的美术仓；CONTRIBUTING、美术说明与设计输入说明也有类似表述。工程工具已经支持外部贡献者自己的母版目录，应在文档区分组织内部管理规范与外部配置路径。

[管线说明](../../dev/pipeline.md)还宣称模板已吸收卡牌去向、克隆和 LoseBlock 的 API 差异；现有 Compat 仅包含 FromCard/CardPlay.GetPlayer 垫片，示例之外的新机制没有这些差异的覆盖证据。应收缩到实际适配与已验证范围，新增调用按双目标原版/API 核对，不继承其他项目的兼容承诺。

## 修复与复验顺序

先解决 F01–F03：保护模型初始化、统一内容发现、修正安装输出的版本声明。随后解决输入路径映射与 X 费用导表，补分批设计覆盖流程及通用机制/可选模块的最小示范，最后统一公开与内部配置口径。

回归应保护实际缺陷：错误模型必须被拦截或明确报错；中间基类的具体卡必须进入所有审计；两个安装布局的目标声明都须正确；JPEG/另名目录应由显式映射支持；X 必须正确导出。文档完成后，按[专项审查清单](checklist.md)重新验证两条路径，再分别进行自然进度、菜单、战斗、奖励、存读档、多人和可选模块的游戏内验收。
